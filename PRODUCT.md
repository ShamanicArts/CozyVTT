# Product

## Register

product

## Users

CozyVTT serves game masters, players, spectators, and self-hosting instance
administrators across preparation and live tabletop sessions. Game masters need
to move quickly between maps, characters, creatures, scene tools, conversation,
and session state without losing the table. Players need a focused view of the
shared fiction, their characters, relevant mechanics, and current choices.
External agents and plugins are first-class operators through the same
application capabilities, while the ordinary interface remains designed for the
humans playing the game.

Desktop and laptop users need the complete authoring workspace. Tablet and
mobile users need a genuine play surface for chat, rolls, character control,
map viewing, token movement, initiative, and consequential approvals rather than
a desktop-only rejection screen.

## Product Purpose

CozyVTT is a self-hosted tabletop workbench for preparing and running
narrative-driven roleplaying games. It brings the shared scene, participants,
conversation, mechanics, and campaign tools into one coherent workspace without
forcing a particular genre or game system onto the table.

Success means the map and shared fiction remain central, frequently used tools
are immediately available, completed mechanics recede without disappearing,
and each role sees an appropriate amount of detail. Core features and plugins
compose through the same versioned workspace regions so the interface can grow
without becoming a collection of unrelated panels.

## Brand Personality

Warm, focused, crafted. CozyVTT should feel welcoming and game-aware while
remaining sleek, compact, and dependable during long sessions. Its character
comes from careful proportions, responsive state, authored campaign content,
and restrained detail rather than a literal fantasy material or ornamental
tabletop skin.

## Anti-references

- A generic dashboard made from repeated equal-weight cards and hero metrics.
- A fantasy-themed interface that relies on wood, parchment, medieval type, or
  other genre assumptions for its identity.
- A direct visual copy of Shuv to Code or another developer tool. STC is a
  reference for spatial hierarchy, density, continuous activity presentation,
  and quiet stateful chrome, not a template.
- Page-wide decorative gradients and glass panels used as the default structure.
- Every chat message, dice result, system notice, and tool operation presented as
  a separate prominent box.
- Plugin interfaces that inject arbitrary unscoped UI, bypass shared components,
  or determine the campaign shell for everyone.
- Desktop layouts merely squeezed onto a small screen, horizontal overflow, or a
  mobile holding screen in place of useful play.
- Dense mechanics permanently occupying the interface after their consequence is
  understood.

## Design Principles

1. Treat the campaign as a workbench: map, shared fiction, and current action
   outrank application chrome.
2. Borrow STC's clarity, compact spatial roles, and continuous activity flow
   while preserving CozyVTT's own game-facing character.
3. Use cards for discrete authored objects when they improve recognition; use
   alignment, lists, sections, rails, and tonal surfaces for ordinary structure.
4. Keep active, failed, and consequential mechanics visible. Collapse completed
   detail into readable summaries with progressive disclosure.
5. Keep the shell genre-neutral. Let campaigns, game systems, themes, and plugins
   provide contextual flavour without compromising control legibility.
6. Give the VTT ownership of stable workspace regions. Let plugins add, remove,
   reorder, resize, and populate those known regions through versioned,
   lifecycle-owned contracts, but not replace the whole campaign shell.
7. Make core features use the same layout and contribution paths offered to
   plugins so extensibility remains exercised and coherent.
8. Design responsive layouts around the user's role and current task rather than
   preserving desktop geometry at every viewport.
9. Trust familiar controls, position, grouping, and visible state. Remove copy
   that does not change a decision, action, interpretation, or safety outcome.

## Accessibility & Inclusion

Target WCAG 2.2 AA for product chrome, text, focus, and controls. Support full
keyboard navigation, visible focus, reduced motion, scalable text, and both
comfortable and compact density. Never rely on colour alone for role, disposition,
selection, visibility, initiative, health, wall type, or other game state.

Maintain useful player operation on mobile and tablet. Preserve clear touch
targets and assistive names for compact or icon-only controls. Responsive
reordering must retain a logical reading and focus order, and every collapsed
mechanic or plugin contribution must remain reachable to assistive technology.
