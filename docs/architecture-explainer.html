Repository reconnaissance / fork design brief

From a capable VTT to an extensible tabletop kernel.

CozyVTT is a healthy conventional full-stack application with useful internal seams. It is straightforward to fork and modify, but it is not yet a runtime plugin platform, renderer-neutral engine, or safe agent control surface.

The right name: a hexagonal modular monolith with a microkernel plugin architecture. Add a command/query bus for every human, network, plugin, and agent action; use Strategy/Bridge-style renderer adapters around a renderer-neutral scene kernel.

01 / Current topology

How CozyVTT is assembled today

The repository is a deployable modular monolith: React in the browser, Express and Socket.IO in one backend process, PostgreSQL through Prisma, and local filesystem uploads. The lines look clean at the package level; inside them, handlers often own too many concerns.

Strong foundations

Strict TypeScript, clear monorepo split, pure drawing functions, normalized client state, composed RBAC, domain-grouped socket registrars, and no import cycles.

Architectural reality

The folders are modular-looking, but most business actions are implemented directly inside HTTP or socket adapters. That makes transport a de facto application layer.

Highest-risk seam

Tokens, walls, fog, lights, and annotations are whole JSON fields. Read–modify–replace updates can silently overwrite concurrent changes.

02 / Runtime path

One token move crosses every boundary

A token move is the best first refactoring slice: authorization, validation, scene state, persistence, visibility, and broadcast all meet here. Today the socket handler coordinates them directly.

Current token-move sequence

The database commit and realtime publication are not one atomic operation.

Why this matters for agents:

Two humans can already race. Agents operate faster and concurrently, so a command layer needs idempotency keys, expected revisions, durable audit, and ordered events before autonomous control is safe.

Hexagonal

Business rules do not know Express, Socket.IO, Prisma, React, Canvas, or MCP.

Modular monolith

Clear domain boundaries without prematurely paying distributed-system costs.

Event-driven, not event-sourced

Durable domain events and an outbox first; full event sourcing is optional, not required.

07 / Runtime extensibility

A microkernel, not a folder of callbacks

The kernel owns identity, policy, commands, events, registries, compatibility, and lifecycle. Plugins contribute through narrow versioned contracts. Untrusted code never receives raw database, socket, filesystem, or network access.

Trusted bundled modules

Can use native TypeScript/React contracts. Suitable for first-party renderers, core game systems, and performance-sensitive layers.

Untrusted runtime plugins

Backend in WASM/WASI or a separate worker/container; frontend in a sandboxed iframe. Default-deny networking and namespaced storage.

08 / Agent control plane

Agents use the same doors as humans

Do not bolt an agent onto Prisma or impersonate a user session. Give agents first-class service identities and expose a generated catalog of typed commands and visibility-filtered queries through MCP or API adapters.

10 / Migration strategy

Refactor by vertical slices, not a rewrite

The sequence deliberately earns safe extension points before enabling third-party runtime code. Each phase leaves the product shippable.

Characterize

Lock behavior with socket contract tests, visual snapshots, concurrency tests, and a provisioned integration database in CI.

Command spine

Introduce Principal, CommandBus, QueryBus, CapabilityService, UnitOfWork, ActionInvocation, and outbox. Move MoveToken first.

Scene consistency

Add map revisions and compare-and-swap immediately; then move frequently edited scene entities to granular storage or an operation log.

Frontend kernel

Extract SessionGateway, SceneStore, ToolStore, input normalization, and registries. Wrap today’s renderer as Canvas2DRendererAdapter.

Prove the ports

Add a second renderer (Pixi/WebGL) and a headless renderer; migrate ruler or AoE as the first registered tool/layer.

Agent adapter

Generate MCP/API tools from the command catalog. Add service identities, scoped grants, approval tokens, cancellation, and subscriptions.

Plugin runtime

Add manifests, compatibility rules, sandboxing, contribution registry, UI slots, lifecycle management, lockfiles, and rollback.

First production milestone:

A human UI, Socket.IO client, REST client, and test agent all invoke the same versioned MoveToken command; concurrent writes reject cleanly; state, audit, and outbox commit together.

Glossary / plain language

The architecture vocabulary

Hexagonal / ports and adapters

The game’s rules sit in the middle. Web servers, databases, sockets, renderers, and agents plug into named interfaces around the edge.

Modular monolith

One deployable application with genuinely enforced internal boundaries. It is not shorthand for “big ball of files.”

Microkernel / plugin architecture

A small trusted host manages lifecycle and registries; separately versioned features contribute through constrained extension points.

Strategy + Bridge

The scene asks a renderer interface to draw; Canvas2D, WebGL, and headless implementations can be selected or exchanged.

Command / query bus

Every action and read has one typed, policy-checked route, regardless of whether its caller is a person, socket, REST endpoint, or agent.

Transactional outbox

The state change and the promise to publish its event commit together, so clients cannot miss an update after the database succeeds.
